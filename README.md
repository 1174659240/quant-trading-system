# 量化交易系统

A 股日线量化研究系统，以及基于同一套引擎的 Windows 桌面交易客户端（规划中）。
代码只依赖 pandas / numpy，数据来自免费公开源。

研究侧已经交付三条冻结策略；产品侧的目标是把引擎封装成客户端，做到自动下单、一键清仓、
持仓与收益展示、策略切换、数据日更。客户端目前只有设计规格，还没有代码。

本项目用于研究与工程验证，不构成投资建议，也不承诺收益。回测能过不代表实盘能赚；
接真钱之前请读 [`docs/实盘接入与合规.md`](docs/实盘接入与合规.md)。

## 1. 目前的状态

- **引擎**：回测撮合、费用（佣金/印花税/过户费/滑点）、T+1、整手、涨跌停不可成交、
  单票成交量参与上限、风控链，回测与实盘共用同一份代码。
- **数据湖**：3.8 GB，5,575 只股票，2016–2024 为主，另有 2007–2016 与 2001–2005 两个历史段。
  分层为 raw / processed / holdout，holdout 带锁。数据可以用
  `python -m scripts.reproduce_lake` 从公开源重建（约 28 小时，可中断续跑）。
- **策略**：三条，见下一节。每条都有预注册、样本内诊断、多重检验与冻结报告。
- **风险层**：市场级极端清仓（E 层）默认开启，只对快速深跌有效的边界写在报告里。
- **下单通道**：CSV 半自动与模拟盘可用；QMT 适配只写了接口，没有实测。
- **桌面客户端**：未实现，本文第 3–6 节是规格。
- **数据日更**：未实现，目前靠手工跑命令。

## 2. 三条策略

| 策略 | 定位 | 样本内 2017–2024 | 历史 2008–2016 | 样本外 2025-01~2026-10 |
|---|---|---|---|---|
| 小盘成长 v1.0（cap25） | 卫星仓，进攻，小容量 | 年化 9.48%，夏普 0.460，MDD −31.85% | 年化 18.07%，0.709，−49.89% | 年化 21.50%，1.118，−16.24%（已消费一次） |
| 红利低波 | 底仓，防守 | 年化 7.63%，0.483，−22.84% | — | 参数被看过数据，样本外结论作废 |
| 红利低波增强 | 同一份选股，只改执行 | 年化 9.53%，0.621，−21.66% | — | 同上 |

小盘成长的信号真实但很弱，超额主要来自小盘、低流动性、高波动这组 beta。长期合理预期
9–12%，不要按 20% 做预算。红利低波相对同池等权没有优势。

口径、失效条件与复现命令见 [`docs/策略报告/`](docs/策略报告/README.md)，机器可读台账是
[`docs/策略报告/registry.json`](docs/策略报告/registry.json)。改任何因子或参数即视为新版本，
旧的样本外结论随之作废。

约束：零杠杆、不融资融券、不做空、不碰衍生品；只做日线低频；只做沪深两市。

## 3. 客户端规格

### 3.1 自动下单

日常流程全自动，不需要人工确认：15:05 采集行情与估值，15:30 用当日收盘算信号，生成次日目标权重；
次日 09:15 生成订单，09:25 前过护栏，09:30 起按限价单分批报出。

- 只用限价单，不用市价单；单笔偏离最新价超过 5% 直接拒绝。
- 单票、单日、单笔金额上限、白名单、单日订单数上限走 `quant/guard.py`，与回测同一套参数。
- 每笔订单带 `(策略版本, 交易日, 代码, 方向, 数量)` 幂等键，进程重启不会重复报单。
- 任何环节不确定（数据未就绪、账本对不上、券商未登录、护栏拒绝）都不报单，界面写清原因。
- 验收：模拟盘连跑 20 个交易日，订单与人工核对表逐笔一致；重复启动不产生重复委托。

### 3.2 一键清仓

按下去就执行，但要防误触。

1. 点红色常驻按钮，弹出清单：全部可卖持仓、预估回款、预估费用、预计到账时间。
2. 勾选确认，再输入确认词「清仓」，不接受回车跳过。
3. 3 秒倒计时结束后按钮才可用。

执行时绕过策略与组合风控，直接对全部可卖持仓下卖单。可卖 = 持仓 − 当日买入（T+1）− 停牌 − 跌停封死。

卖不掉的部分要如实显示：涨跌停、停牌、无对手盘的，列出原因与数量，当日按 30 秒重试；
收盘仍未卖出的写进次日待办。确认后不提供取消，只提供停止重试；已报出的单要撤需另走撤单流程。
全过程写本地审计日志，只追加。

验收：模拟盘对 50 只持仓清仓，可卖标的在一个交易日内出清；人为制造跌停股，界面正确显示卖不掉的数量。

### 3.3 持仓与收益

- 持仓页：代码、名称、数量、可用数量、成本价、现价、市值、浮盈、占比、行业、流动性档位。
- 今日页：当日盈亏、成交、费用、净值。
- 累计页：净值曲线（策略、同池等权、中证 1000）、累计与年化收益、夏普、最大回撤、当前回撤、
  滚动 1 年与 3 年收益、逐年收益。
- 暴露页：总仓位、现金比例、行业占比与上限余量、单票上限余量、前十大集中度。
- 净值口径必须与回测一致：净值 = 现金 + 持仓市值（收盘价，含费用），收益按净值算，不按价格算。
- 验收：同一交易日，客户端净值与同一份成交回放的净值误差小于 1 个基点。

### 3.4 策略切换

- 策略列表从 `registry.json` 读，显示名称、版本、定位、样本内外业绩、状态。
- 当前策略卡片显示版本、下次调仓日、持仓数。
- 切换时先给差异预览（预计换手、预计费用、行业暴露变化、需要卖出的标的），二次确认后在下一个
  调仓日生效，不在盘中换。旧策略的持仓与净值存档保留。
- 冻结策略的关键参数只读展示，避免手改参数还以为是原策略。改参数等于发布新版本。

### 3.5 数据日更与结算

- 每交易日 15:05 更新日线（东财、腾讯、新浪三源互备）、估值、停牌与涨跌停、分红除权。
- 校验：与交易日历对账、与上一交易日比对数、抽查非正价、重复行、缺口；不过不进入下一步。
- 15:30 结算：更新市值、盈亏、净值、费用，生成当日报告。
- 夜间增量：财务按 `NOTICE_DATE` 入库，不使用未公告的报告期；另类数据（解禁、质押、预告、快报）。
- 断网时进入只读模式，可看历史不能下单，恢复后补齐并提示补算了哪几天。
- 验收：连续 5 个交易日无人值守，净值与人工计算一致；人为断网一天，界面标记缺口且不报单。

### 3.6 版本维护

- 策略与引擎分离：策略是「因子清单 + 参数 + 版本号」的配置，不是可执行代码。客户端只从签名的
  策略包加载参数，不接受远程下发的任意代码。
- 发布：研究侧冻结 → 生成带校验和与签名的策略包 → 推送到更新源 → 客户端校验 →
  可选影子回放最近 60 个交易日 → 通过则提示下个调仓日生效，失败保持旧版本并说明原因。
- 回滚：保留最近 5 个版本与完整账本，一键回滚，同样在调仓日生效。
- 引擎更新走安装包，与策略包解耦；升级前跑内置自检。
- 健康页显示数据新鲜度、上次结算时间、通道状态、护栏拦截计数、磁盘占用；日志按天切分保留 90 天，
  可一键导出诊断包。
- 验收：下发一个故意损坏的策略包，客户端拒绝加载并保持旧版本；回滚后净值连续。

## 4. 客户端架构

```
┌─────────────────────── Windows 桌面客户端（本地单机） ───────────────────────┐
│ 界面层  持仓 · 收益 · 策略设置 · 一键清仓 · 健康页   （只调用服务层，不算因子）    │
├───────────────────────────────────────────────────────────────────────────┤
│ 服务层  调度器（15:05 更新 / 15:30 结算 / 次日 09:15 下单 / 夜间增量）           │
│         账户服务（持仓·现金·可用数量）   订单服务（护栏→幂等→通道→回报）          │
│         策略服务（加载冻结参数·算权重·切版本）   报表服务（日/月/年·净值曲线）      │
├───────────────────────────────────────────────────────────────────────────┤
│ 引擎层  quant/*（撮合、费用、T+1、涨跌停、风控链、因子、评估）                     │
├───────────────────────────────────────────────────────────────────────────┤
│ 数据层  本地 Parquet 湖（raw / processed / live / history）+ 日更 + 完整性校验    │
├───────────────────────────────────────────────────────────────────────────┤
│ 通道层  paper（默认） → QMT（券商） → CSV 半自动         全部经 PreTradeGuard     │
└───────────────────────────────────────────────────────────────────────────┘
```

技术选型还没定，倾向 PySide6（Qt），引擎同进程，直接用 `quant/*`，代价是首次引入 GUI 依赖。
备选 Electron 加本地 HTTP 服务，界面生态好，但要双语言双进程。

设计约束：

1. 单实例锁：同一账户只允许一个进程，第二个实例拒绝启动。
2. 不确定就不交易，并把原因显示出来。
3. 订单、结算、日更都有幂等键，崩溃重启可安全重放。
4. 所有决策写不可变日志。
5. 券商账号与令牌用 Windows DPAPI 加密存盘，不上传，不采集持仓到云端。
6. 客户端不修改 `processed/` 与历史归档，自己的数据写 `live/` 与 `client/`。
7. 时间统一用 `Asia/Shanghai`，交易日历来自本地数据层，不用系统时钟猜。
8. 只接受签名通过的策略包。

## 5. 失败时怎么办

| 场景 | 行为 |
|---|---|
| 收盘数据未就绪或校验失败 | 不生成信号、不报单，界面提示，次日补算并标注 |
| 券商未登录或通道超时 | 只重试不改单；09:35 仍未连通则当日放弃，写待办 |
| 部分成交或涨跌停买不进 | 未成交部分留现金或继续持有，次日重算，不追价 |
| 进程崩溃或断电 | 重启按幂等键对账，已报单不重复；账本以券商回报为准 |
| 策略包损坏或签名不符 | 拒绝加载，保持上一版本 |
| 一键清仓遇到跌停 | 列出卖不掉的数量，当日重试，收盘转次日待办 |
| 数据源全挂 | 只读模式，不交易，不用旧数据硬算 |

## 6. 路线图

- M0 研究冻结：三条策略、台账、证据归档。已完成（`v1.0-growth-cap25-20261022`）。
- M1 数据日更与收盘结算：命令行，无界面。验收是连续 5 日无人值守、净值与人工一致。
- M2 客户端只读版：持仓、收益、净值曲线、健康页，不接券商。验收是与回测净值误差小于 1bp。
- M3 模拟盘自动下单：调度器、订单服务、护栏、幂等、审计。验收是 20 个交易日逐笔一致。
- M4 实盘小资金与一键清仓：QMT 通道、三步确认、失败重试、审计。验收是清仓演练。
- M5 策略热更新与回滚：签名策略包、影子回放、版本切换。验收是损坏包被拒绝、回滚后净值连续。
- M6（远期）：多策略并行、移动端只读、券商多通道。

顺序上先把数据与账本做扎实（M1–M2），再谈自动下单（M3）。实盘前要有模拟盘 20 日的执行证据。

## 8. 跑起来

```bash
# 环境：Python 3.10+，pandas / numpy；读写 parquet 需要 pyarrow
python tests/run_all.py                 # 210 项离线自测
python -m quant doctor                  # 环境自检，报告写 results/doctor.md

# 数据湖：一条命令从公开源重建（约 28 小时，可中断续跑）
python -m scripts.reproduce_lake --list
python -m scripts.reproduce_lake
python -m scripts.reproduce_lake --verify-only    # 与参考计数对账

# 或者手工分阶段
python -m quant lake init
python -m quant lake universe
python -m quant lake crawl --source auto
python -m quant lake process
python -m quant lake parquet
python -m quant lake status

# 回测与因子
python -m scripts.run_backtest --strategy multifactor
python -m scripts.factors

# 小盘成长：样本内 → 稳健性 → 样本外（holdout 只用一次）
python -m scripts.growth_backtest --spec QN
python -m scripts.growth_robust --fast
python -m scripts.growth_holdout

# 模拟盘与半自动实盘（默认只出订单文件，不下单）
python -m scripts.paper_trade plan --out results/paper/orders.csv
python -m scripts.trade suggest --out results/orders/latest.csv
python -m scripts.trade check --orders results/orders/latest.csv
```

## 10. 已知限制

- **收益预期**：小盘成长长期合理预期 9–12%/年，代价是 −30% 级回撤。无杠杆，20%/年在本口径下不可达。
- **超额来源**：主要是小盘、低流动性、高波动这组 beta（2017 年为负，2021–2023 爆发，2024 归零），
  不是稳定的 alpha。
- **统计显著性**：DSR 按最宽松的 N=4 也只有 0.59，PBO 0.65。可能有真信号，但统计上不显著。
- **执行**：回测假设涨跌停不成交，但无法模拟排队，实盘成交率会低于回测。滑点用 5 档事前分档。
- **数据偏差**：财务是修订后值；历史层缺 298 只（偏乐观）；2025 年后的退市事件缺失；
  行业 PIT 最早到 2014-12。
- **容量**：100 万本金没有压力；1,000 万时最低流动性档（ADV 约 2,500 万）开始吃力。
- **未实现**：客户端、QMT 实测、自动下单接入都还没有。
- **已知测试问题**：`test_factors::test_every_registered_factor_computes` 在跨套件连续运行时
  会因全局状态污染偶发失败（`fmcap_q05`），单独跑通过，不影响策略结论。
