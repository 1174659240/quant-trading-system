# 量化交易系统 · A 股日线策略研究与交易客户端

一套**只依赖 pandas / numpy** 的 A 股日线量化系统：数据湖 → 因子 → 策略 → 回测 → 风险层 → 下单通道。
研究侧已交付三条**经过预注册与样本外检验**的策略；产品侧的目标是把这套引擎封装成 **Windows 桌面客户端**，
做到自动下单、一键清仓、持仓与收益可视化、策略切换、数据日更与在线维护。

> 本项目是研究与工程验证系统，**不构成投资建议，也不承诺收益**。回测能过不代表实盘能赚。
> 接真钱前请读 [`docs/实盘接入与合规.md`](docs/实盘接入与合规.md)。

## 1. 项目定位

两条并行的主线，共用同一套引擎：

1. **研究系统（已交付）**——把「想法」变成「可冻结的策略」：
   预注册 → 样本内诊断 → 多重检验（DSR/PBO/置换/bootstrap/WFA/IS-OOS）→ 样本外一次性验收 → 冻结与归档。
2. **交易客户端（规划）**——把「冻结的策略」变成「每天能用的软件」：
   数据日更 → 收盘结算 → 生成订单 → 自动下单 → 持仓与收益展示 → 一键清仓 → 策略热切换与维护。

设计上有一条硬边界：**研究可以慢、可以反复；交易必须快、必须确定、必须可审计。**
所以客户端不重新实现任何因子或撮合逻辑，它只是引擎的「外壳 + 调度器 + 安全护栏」。

## 2. 已冻结的策略（三条，同一引擎）

| 策略 | 定位 | 样本内 2017–2024 | 历史样本 2008–2016 | 样本外 2025-01~2026-10 | 结论与边界 |
|---|---|---|---|---|---|
| **小盘成长** v1.0（cap25） | 卫星仓、进攻、小容量 | 年化 **9.48%** / 夏普 0.460 / MDD −31.85% | 年化 18.07% / 0.709 / −49.89% | 年化 **21.50%** / 1.118 / −16.24%（已消费，一次性） | 信号真实但很弱；超额主要来自小盘/低流动性/高波动 beta；长期合理预期 9–12%，不要按 20% 做预算 |
| **红利低波** | 底仓、防守 | 年化 7.63% / 0.483 / −22.84% | — | 样本外已污染（参数被看过数据） | 与同池等权（+12.25%）相比并不占优；纯红利 top50 样本内 +174% 是另一回事 |
| **红利低波增强** | 同一份选股，只改执行 | 年化 9.53% / 0.621 / −21.66% | — | 同上 | 「非调仓日不交易」带来 +2pp/年、费用从 16.9 万降到 3.7 万 |

三条策略的口径、业绩、失效条件与复现命令见 [`docs/策略报告/`](docs/策略报告/README.md)，
机器可读台账 [`docs/策略报告/registry.json`](docs/策略报告/registry.json)（改任何因子/参数即视为新版本，旧样本外结论作废）。

**能力边界（写死，不做）**：零杠杆、零融资融券、不做空、不碰衍生品；只做日线低频；只做沪深两市（不含北交所/B 股）。

## 3. 桌面客户端 · 功能规格

> 本节是**目标产品规格**（v1），尚未实现。每条都给了交互、后端约束与验收标准，便于直接排期施工。

### 3.1 自动下单

- **日常流程**（全自动，无需人工点确认）：
  `15:05` 采集当日行情与估值 → `15:30` 用 T 日收盘算信号 → 生成次日目标权重 →
  `次日 09:15` 生成订单 → `09:25` 前经护栏校验 → `09:30` 起按限价单分批报出。
- **只允许限价单**，禁止市价单；单笔偏离最新价超过 5% 直接拒绝（防手滑）。
- **单票/单日/单笔金额上限、白名单、单日订单数上限**全部走 `quant/guard.py`，与回测同一套参数。
- **幂等**：每笔订单带 `(策略版本, 交易日, 代码, 方向, 数量)` 幂等键，进程重启不会重复报单。
- **失败即停（fail-closed）**：数据未就绪、账本对不上、券商未登录、护栏拒绝 → 当日**不报单**并在界面红字提示，绝不「猜着下单」。
- 验收：模拟盘连跑 20 个交易日，订单与「人工核对表」逐笔一致；重复启动不产生重复委托。

### 3.2 一键清仓（三次确认，无条件执行）

这是整个客户端**优先级最高**的按钮，设计原则是「按下去就必须执行」，但要防误触。

- **交互三步**：
  1. 点击「一键清仓」（红色常驻按钮）→ 弹出清单：全部**可卖**持仓、预估回款、预估费用、预计 T+1 到账；
  2. 勾选「我已确认卖出全部持仓」→ 输入确认词 `清仓`（不接受回车跳过）；
  3. 3 秒倒计时结束后按钮才可用 → 点击执行。
- **执行语义**：绕过策略与组合风控（不再问「该不该卖」），直接对**全部可卖持仓**下卖出单；
  可卖 = 持仓 − 当日买入（T+1）− 停牌 − 跌停封死。
- **卖不掉要如实说**：涨跌停/停牌/无对手盘的部分，界面列出「未成交原因 + 数量」，并在当日剩余时段按 30 秒重试；
  收盘后仍未卖出的，写进次日待办并高亮。
- **不可取消**：确认后不提供「取消」，只提供「停止重试」（已报出的单不撤，撤单需另走撤单流程）。
- **全程审计**：谁点的、几点点的、清单快照、每笔委托与成交、失败原因，写本地审计日志（只追加、不可改）。
- 验收：模拟盘上对 50 只持仓执行清仓，全部可卖标的在 1 个交易日内卖出；人为制造跌停股，界面正确显示「卖不掉 N 股」。

### 3.3 持仓与收益展示

- **持仓页**：代码/名称、数量、可用数量、成本价、现价、市值、浮动盈亏、占比、所属行业、流动性档位（1–5）。
- **今日页**：当日盈亏（金额与百分比）、当日成交、当日费用、当日净值。
- **累计页**：净值曲线（策略 vs 同池等权 vs 中证 1000）、累计收益、年化、夏普、最大回撤、当前回撤、
  滚动 1 年/3 年收益、逐年收益表。
- **暴露页**：总仓位、现金比例、行业门类占比与上限余量、单票上限余量、前十大持仓集中度。
- **口径必须与回测一致**：净值 = 现金 + 持仓市值（收收盘价，含费用），收益按净值算，不按价格算。
- 验收：同一交易日，客户端净值与「用同一份成交回放出的回测净值」误差 < 1 个基点（除四舍五入）。

### 3.4 策略设置与切换

- **策略列表**：从台账 `registry.json` 读取，显示名称、版本、定位、样本内/样本外业绩、状态（冻结/实验/停用）。
- **当前策略卡片**：显示正在执行的策略版本、下次调仓日、持仓数、剩余可用参数。
- **切换策略**：选择新策略 → 显示差异预览（预计换手、预计费用、行业暴露变化、需要卖出的标的）→ 二次确认 →
  **在下一个调仓日生效**（不在盘中换策略）。切换动作写审计日志，旧策略的持仓与净值曲线存档不丢。
- **参数只读**：冻结策略的关键参数（因子、权重、持仓数、行业上限、成本假设）在客户端**只读展示**，
  防止「手一抖改了参数还以为是原策略」。要改参数 = 发布新版本（见 3.6）。
- **多策略并存（v1.1）**：允许「底仓策略 + 卫星策略」两个实例同时运行，各自独立账本与净值，合并展示总仓位。

### 3.5 数据日更与收盘结算

- **每个交易日 15:05 自动更新**：当日日线（东财 → 腾讯 → 新浪三源互备）、估值、停牌与涨跌停状态、分红除权事件。
- **完整性校验**：与交易日历对账、与上一交易日比对数、抽查非正价/重复行/缺口；**校验不过不进入下一步**。
- **15:30 收盘结算**：更新持仓市值、当日盈亏、累计净值、费用明细；生成当日报告（Markdown + 客户端卡片）。
- **夜间任务**：财务数据增量（按 `NOTICE_DATE` 入库，绝不使用未公告的报告期）、另类数据（解禁/质押/预告/快报）。
- **离线降级**：断网时客户端进入只读模式（可看历史，不可下单），恢复后自动补齐并提示「补算了哪几天」。
- 验收：连续 5 个交易日无人值守运行，净值与人工计算一致；人为断网 1 天，界面正确标记数据缺口且不报单。

### 3.6 策略更新与维护（做成软件后最容易被忽视的部分）

- **策略与引擎分离**：策略 = 「因子清单 + 参数 + 版本号」的配置文件（JSON），**不是可执行代码**。
  客户端只从**已签名的策略包**加载参数；禁止在线下发任意 Python 代码（这是最大的安全风险）。
- **发布流程**：研究侧冻结 → 生成 `strategy-<id>-<version>.json`（含 spec、业绩、校验和、签名）→
  推送到更新源 → 客户端检查更新 → 校验签名与校验和 → （可选）用最近 60 个交易日做影子回放 →
  通过则提示「有新版本，下个调仓日生效」，失败则保持旧版本并提示原因。
- **回滚**：保留最近 5 个策略版本与完整账本，一键回滚到上一版本（同样在调仓日生效）。
- **引擎更新**：客户端本体走独立更新通道（安装包），与策略包解耦；引擎升级前先跑内置自检（`doctor` + 测试子集）。
- **运维可见**：健康页显示数据新鲜度、上次结算时间、通道状态、护栏拦截计数、磁盘占用；
  日志按天切分、保留 90 天；一键导出「诊断包」（脱敏后的日志 + 配置 + 最近 30 天成交）。
- 验收：下发一个故意损坏的策略包，客户端拒绝加载并保持旧版本；回滚后净值曲线连续无断点。

## 4. 客户端架构（目标形态）

```
┌─────────────────────── Windows 桌面客户端（本地单机） ───────────────────────┐
│ 界面层  持仓 · 收益 · 策略设置 · 一键清仓 · 健康页   （只调用服务层，不算因子）    │
├───────────────────────────────────────────────────────────────────────────┤
│ 服务层  调度器（15:05 更新 / 15:30 结算 / 次日 09:15 下单 / 夜间增量）           │
│         账户服务（持仓·现金·可用数量）   订单服务（护栏→幂等→通道→回报）          │
│         策略服务（加载冻结参数·算权重·切版本）   报表服务（日/月/年·净值曲线）      │
├───────────────────────────────────────────────────────────────────────────┤
│ 引擎层  quant/*（本项目：撮合、费用、T+1、涨跌停、风控链、因子、评估）             │
├───────────────────────────────────────────────────────────────────────────┤
│ 数据层  本地 Parquet 湖（raw / processed / live / history）+ 日更 + 完整性校验    │
├───────────────────────────────────────────────────────────────────────────┤
│ 通道层  paper（默认） → QMT（券商） → CSV 半自动         全部经 PreTradeGuard     │
└───────────────────────────────────────────────────────────────────────────┘
```

**技术选型（待拍板的 ADR）**：

| 方案 | 优点 | 代价 | 倾向 |
|---|---|---|---|
| **A. PySide6（Qt）+ 引擎同进程** | 单一语言，直接调用 `quant/*`，无桥接损耗 | 需引入 Qt 依赖（首次引入 GUI 依赖） | 推荐 |
| B. Electron + 本地 HTTP 服务 | 界面生态好，与 DSH 客户端技术栈一致 | 双语言、双进程，需要额外守护与打包 | 备选 |

**关键设计决策（沿用研究侧结论）**：

1. **单实例锁**：同一账户只允许一个客户端进程运行，第二个实例直接拒绝启动。
2. **fail-closed**：任何环节不确定（数据/账本/通道/护栏）都选择「不交易」，并把原因显示出来。
3. **幂等键**：订单、结算、日更都有幂等键，崩溃重启可安全重放。
4. **审计只追加**：所有决策（信号、目标权重、订单、成交、清仓、切策略）写不可变日志。
5. **凭据本地加密**：券商账号与令牌用 Windows DPAPI 加密存盘，绝不上传；客户端不采集持仓到云端。
6. **只读研究数据**：客户端不修改 `processed/` 与历史归档，自己的数据写 `live/` 与 `client/`。
7. **时间口径**：所有时间用 `Asia/Shanghai`，交易日历来自本地数据层，不用系统时钟猜。
8. **策略包签名**：只接受签名通过的参数包；拒绝任何形式的远程代码执行。

## 5. 失败模式与应对（先想清楚怎么坏）

| 失败场景 | 客户端行为 |
|---|---|
| 收盘数据未就绪 / 校验失败 | 不生成信号、不报单；界面红字提示，次日补算并标注 |
| 券商未登录 / 通道超时 | 只重试不改单；超过 09:35 仍未连通则当日放弃，写待办 |
| 部分成交 / 涨跌停买不进 | 未成交部分留现金或继续持有，次日重新计算，不追价 |
| 进程崩溃 / 断电 | 重启后按幂等键对账，已报单不重复；账本以券商回报为准 |
| 策略包损坏 / 签名不符 | 拒绝加载，保持上一版本，提示原因 |
| 一键清仓时个股跌停 | 如实列出「卖不掉 N 股」，当日按 30 秒重试，收盘后转次日待办 |
| 数据源全挂（东财/腾讯/新浪） | 只读模式；不交易；提示「数据不可用」而不是用旧数据硬算 |

## 6. 路线图

| 里程碑 | 内容 | 验收 |
|---|---|---|
| **M0 研究冻结** | 三条策略 + 台账 + 证据归档 | ✅ 已完成（`v1.0-growth-cap25-20261022`） |
| **M1 数据日更 + 收盘结算** | 每交易日自动更新、校验、结算、出日报（无界面，命令行） | 连续 5 日无人值守，净值与人工一致 |
| **M2 客户端只读版** | 持仓、收益、净值曲线、健康页（不接券商） | 与回测净值误差 < 1bp |
| **M3 模拟盘自动下单** | 调度器 + 订单服务 + 护栏 + 幂等 + 审计（`paper` 通道） | 20 个交易日订单与人工核对表逐笔一致 |
| **M4 实盘小资金 + 一键清仓** | QMT 通道、清仓三步确认、失败重试、审计 | 清仓演练：可卖标的 1 日内出清；跌停股正确报「卖不掉」 |
| **M5 策略热更新与回滚** | 签名策略包、影子回放、版本切换、回滚 | 损坏包被拒绝；回滚后净值连续 |
| M6（远期） | 多策略并行、移动端只读、券商多通道 | — |

**排序理由**：先把「数据对不对、账本准不准」做扎实（M1–M2），再谈自动下单（M3）；
实盘前必须有模拟盘 20 日的执行证据；一键清仓必须在实盘前演练通过。

## 7. 仓库结构

```
量化交易系统/
├─ quant/                  引擎（纯 pandas/numpy，无网络副作用）
│  ├─ data/                行情契约、缓存、三源联网抓取、日历、分红
│  ├─ indicators.py        均线/RSI/MACD/布林/ATR/KDJ/OBV/重采样
│  ├─ strategy/            策略契约 + 10 个内置策略
│  ├─ backtest/            撮合、组合（T+1/整手/费用）、绩效指标
│  ├─ factors/             多因子 + 成长因子 + 筹码因子 + 事件/前沿因子
│  ├─ gateway/             下单通道（csv / paper / qmt）+ 订单护栏 + 账本
│  ├─ risk.py regime.py    风控 overlay 与市场级危机分量
│  ├─ lake.py              数据湖（raw / processed / holdout）
│  └─ doctor.py plugins.py cli.py
├─ scripts/                研究脚本（回测、因子诊断、稳健性、历史采集、holdout 验收…）
├─ tests/                  210 项离线自测（纯 assert，约 2 分钟）
├─ docs/                   文档总索引见 docs/README.md；策略报告在 docs/策略报告/
```

```bash
# 0) 需要 Python 3.10+ 且装有 pandas / numpy（parquet 需要 pyarrow）
python tests/run_all.py                 # 210 项离线自测
python -m quant doctor                  # 环境自检，报告写 results/doctor.md

python -m quant lake crawl --source auto
python -m quant lake process            # 原始 → processed（≤2024-12-31）

python -m quant lake status

python -m scripts.run_backtest --strategy multifactor
python -m scripts.factors

python -m scripts.trade suggest --out results/orders/latest.csv
python -m scripts.trade check --orders results/orders/latest.csv
```

## 10. 已知边界（别把它当「稳赚系统」）

- **收益预期**：小盘成长长期合理预期 9–12%/年，代价是 −30% 级回撤；目标 20%/年在本口径下不可达（无杠杆）。
- **超额来源**：主要来自小盘/低流动性/高波动 beta 簇（2017 为负、2021–2023 爆发、2024 归零），不是稳定 alpha。
- **多重检验**：DSR（按最宽松 N=4）只有 0.59，PBO 0.65；模型「可能有真信号」但**统计上不显著**。
- **执行**：回测假设涨跌停不成交但无法模拟排队；实盘成交率会低于回测。滑点用 5 档事前分档（2–5bp）。
- **数据偏差**：财务为修订后值；历史层 298 只缺口（偏乐观）；2025+ 退市事件缺失；行业 PIT 最早 2014-12。
- **容量**：100 万本金无压力；1,000 万时最低流动性档（ADV 约 2,500 万）开始吃力。
- **未实现**：本文 §3–§6 的客户端是规格，不是代码；QMT 通道未实测；自动下单尚未接入任何券商。
- **自测**：210 项离线自测中，`test_factors::test_every_registered_factor_computes`（`fmcap_q05`）
  在跨套件连续运行时受全局状态污染偶发失败，单独运行可通过——已知问题，不影响策略结论。
