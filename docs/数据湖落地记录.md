## 一之二、Parquet 列式副本（2026-10-17 追加）

精简层与校核集各写一份 Parquet 副本（`processed/parquet`、`holdout/parquet`），**按 `year=YYYY` 分区、每区一个文件**；
`raw` 层保持 CSV 原样不动。CSV 仍是权威数据，Parquet 只是可重建的读取加速副本。

| 层 | 分区数 | 行数 | 代码数 | Parquet 体积 | CSV 体积 | 转换耗时 | 对拍 |
|---|---|---|---|---|---|---|---|
| processed | 9（2016–2024） | 8,557,867 | 5,278 | 178.9 MB | 745 MB | 95 s | 行数/代码数/日期范围 + 抽样 10 只逐值一致 |
| holdout | 2（2025–2026） | 2,343,739 | 5,575 | 52.2 MB | 200 MB | 41 s | 同上 |

- 列类型固定：`symbol` string、`date` date32、价量 float64、`suspended`/`tradable` int8；zstd 压缩。
- 转换是「先写临时目录、成功后整体替换」，失败不会留下半成品；重复转换必须显式 `--overwrite`。
- 读取性能实测（同一台机器、全市场 5278 只 / 855.8 万行）：

  | 路径 | 耗时 | 备注 |
  |---|---|---|
  | 逐只 `read_csv` | 29.3 s | 平均约 5 ms/只，745 MB |
  | Parquet 整层扫描 | **6.2 s** | 扫描 0.34 s + 按代码切组 5.47 s，179 MB |

  端到端 `factor-market` 读取段从 29.3 s 降到 6.2 s；因子计算与回测本身（约 250 s）成为新的瓶颈。
- `lake verify` 现在会把 Parquet 层与 CSV 层对拍，不一致直接列进问题清单。
- 没有 pyarrow 时一切照旧走 CSV；Parquet 命令会提示 `python -m pip install pyarrow`。

## 二、口径（写死在代码里）

1. **不复权入库，复权后算**：`build_factor_index` 用分红送转事件算前复权缩放因子
   `k = (P0 − 现金红利) / (1 + 送股) / P0`，按除权日连乘；`apply_qfq` 把 OHLC 乘上 `k`，另存 `adj_factor` 列；
   成交量/成交额不下调，原始层 `close` 始终是真实现金价。
2. **停牌显式入库**：按交易日历 reindex，缺失交易日填 `suspended=1`、`volume=0`、`amount=0`、OHLC=前收，
   只在「上市首日 ~ 最新日」之间补，不凭空造上市前行情。
3. **校核集加锁**：`holdout/daily/` 默认不可读，调参/选因子只允许碰 `processed/`，避免样本内挑参。

### 4.2 行业 PIT（`ref/industry.parquet`）

- `bs.query_stock_industry(date=年末交易日)`，13 个年度版本 2014-12-31 ~ 2026-10-17，**55,416 行**。
- **确认有 PIT**：`updateDate` 随查询日回溯到当年分类日（2015-12-28 / 2017-12-25 / 2018-12-24 …），
  粒度是**年度**；重组换行业会滞后一年（`600733` 2018-12-28 起 K70 房地产→C36 汽车；`002027` 2016-12-30 起 C39→L72）。
- 每年条数单调增长 2,666（2014）→ 5,558（2026-10-17），与在市数量一致；空行业 34→334（**全是已退市代码**）。
- 坑：`socket.setdefaulttimeout(45)` 下 2025-12-31 只回 4,000 行且 `error_code` 仍是 `"0"`
  → 必须校验「行数 + 代码唯一性」，重试 3 次并 `ensure_bs(force=True)`；超时设 300s。

### 4.3 估值/isST（`valuation/<代码>.parquet`）

- 5,563 只 × 2014 起；单只 12 年 3,107 行实测 7.3–8.4 s，**4 分片并行后 0.24–0.28 只/秒**（≈4s/只），
  全量约 5.5–6.5 小时；文件存在即跳过、`fetch_log/shard` 断点续跑。
- **最终结果（2026-10-18 04:15 完成）**：写入 **5,482 只 / 790 MB**，空表 81 只（全部是 2014 年前就退市的老票），
  失败 0（首轮 33 只 `10002007: 网络接收错误`，续跑一轮补齐）。分片用时 13,751–14,114 s。
- 瓶颈是服务端字符流带宽（单进程内单只延迟会涨到 27–31s），不是连接数。

### 4.3b ST 剔除（`--exclude-st`）

- `quant.valuation.st_matrix()` 只读 `isST` 一列拼「交易日 × 代码」布尔矩阵（5,482 只约 33 s）；
- `MultiFactorStrategy(exclude=...)` 在 `_eligible` 里 `mask &= ~blocked`，ST 不参与选股；
- 实测 ST 占格位 **2.33%**（2016 年末 68 只 → 2019 年末 136 只 → 2024 年末 132 只）。

### 4.4 财务四表（`fundamentals/{profit,balance,cashflow,indicator}/<报告期>.parquet`）

- 按报告期拉全市场（`filter=(REPORT_DATE='...')(SECURITY_TYPE_CODE in (...))`），55 期 2013-03-31 ~ 2026-09-30。
- 行数：profit 285,025 / balance 268,948 / cashflow 278,596 / indicator 285,127；每期每表 8–20 秒
  （分页上限 500 行，一页约 4 秒，14–35 页）。
- **表的覆盖缺口（重要）**：`GBALANCE`/`GCASHFLOW` **整张不含金融业**——`000001`/`600036`/`601318`
  在资产负债表里是 **0 行**（银行/保险/证券用专用模板，专用报表名在数据中心一律「报表配置不存在」）。
  解法是加第四张表 `RPT_F10_FINANCE_MAINFINADATA`（165 列选 24 列），它对全部公司齐全且自带
  `ROEJQ/XSMLL/XSJLL/ZCFZL/BPS/TOTAL_SHARE`。
- **PIT 口径**：`NOTICE_DATE` 与 baostock `pubDate` 20/20 完全一致（最大偏差 0 天）；公告滞后中位

- **修订不可回溯**：东财与 baostock 都只留每报告期一行（修订后值），无版本号 → 报告必须标注轻微后视偏差。
- **退市后仍披露**：`000033`（2017 退市）数据到 2023-09-30，`600087`、`000003` 到 2026-06-30（老三板延续），

### 4.7 固定偏差声明（所有因子/回测报告顶部必须带）

1. 财务为**修订后值**（无版本号，修订偏差不可回滚）；
2. 可用时点用 `NOTICE_DATE`（缺失兜底 `+110 天`），不用报告期；
3. 行业为**年度** PIT，重组后可能滞后一年；
4. 申万行业只有当期快照（`index_component_sw` 无日期参数），仅作描述用；
5. 指数成分只有当前快照 → 幸存者偏差；
6. 退市收益按 CRSP 分层，`−30%` 与 `−100%` 双版本并列；
7. 估值/isST 为逐日快照回填，停牌日沿用最近有效值；
8. **北交所（351 只）在 2014–2026 全区间没有估值（PE/PB/isST）与财务**：baostock universe 不含北交所、
   东财三表按 `SECURITY_TYPE_CODE in ("058001001","058001002")` 过滤也不含 → 它们**不进因子样本**，
   等于系统性排除了一个以中小市值为主的板块，任何“全市场”结论都要读成“沪深两市”；
9. **2014 年前已退市的 81 只老股没有日线**（baostock 只提供 2014 起的完整后复权），
   它们不进回测；这部分的幸存者偏差比 256 只已补退市股小一个量级，但不为零。

### 4.8 股本 PIT（`ref/shares.csv` + `.parquet`，150,154 条变动 / 5,863 只）

- 来源：东财数据中心 **`RPT_F10_EH_EQUITY`**（股本结构变动表），按 `END_DATE` 记每次变动的
  `TOTAL_SHARES` / `LISTED_A_SHARES` / `LIMITED_SHARES` / `H_FREE_SHARE` / `B_FREE_SHARE`，
  301 页 × 500 行 ≈ 6 分钟。
- **踩到的坑（差点写成未来函数）**：`MAINFINADATA.TOTAL_SHARE` / `A_FREE_SHARE` 是**最新股本**，
  不是报告期末股本——实测 `600519` 在 2013–2026 的**每个**报告期都显示 1,252,270,000，
  `605369` 在 2020 年报就显示 2023 年才有的 220,492,949 股。若拿它算历史市值/规模因子，
  等于把未来的送转增发全部提前知道。已弃用该列做时间序列（只保留 `mainfin` 里作“最新股本”参考）。
- **PIT 取值**：`refdata.shares_at(day)` 只取 `change_date <= day` 的最近一条，早于首个变动日直接缺席
  （不用未来值兜底）。校验：`605369` 在 2020-12-31 = 80,000,000 / 流通 20,000,000（IPO 当年真实值），
  `601577` 在 2018-12-31 = 3,421,553,754 / 流通 342,155,376，`688981` 在 2020-12-31 = 7,703,507,527 / 流通 1,040,231,223。
- 覆盖：真实代码 5,863 只，其中 5,409 只在 universe 内；universe 缺 154 只（多为 2014 前退市，天生没有变动记录）。
  另有 2,214 个东财内部代码（`A0xxxx`/`A2xxxx`，新三板/摘牌主体）保留原始行并标 `is_real_code=0`，
  下游一律过滤。
- **不能当权威的旁证**：baostock `query_profit_data` 的 `liqaShare` 抽样 65 个观测与东财最新股本比，
  P90 偏差 140%——但根因是东财列错，不是 baostock 错：`601577` 的 `liqaShare=342,155,376` 与
  `RPT_F10_EH_EQUITY` 完全一致。教训：对拍前先确认“哪一列是时点值”。

### 4.11 PIT 分红 + 换手宽表（2026-10-18 追加，任务一/二的数据底座）

- **分红** `ref/dividends.parquet`（36,611 行 / 5,167 只 / 45 期 2013-12-31~2024-12-31）：
  东财 `RPT_SHAREBONUS_DET`，`python -m quant lake dividends` 约 32 秒重建。口径是「已实施」——
  `ex_date <= t` 的过去 365 个自然日每股现金分红之和（`quant.dividends.dps_panel`），**不含预案期**，
  所以 `div_yield` 天然保守（公告前不可知）。校验：茅台 2024-06-19 除息每股 30.876 元，
  TTM@2024-06-21 = 56.79、@2024-12-31 = 54.758（= 30.876 + 23.882）。

  ②`dps_panel` 必须**先铺自然日日历再 rolling**——除息日经常不在交易日上，直接对面板日期 reindex 会丢事件。
- **换手宽表** `ref/turn_panel.parquet`（2,676 × 5,329，float32，53 MB）：`valuation` 层 `turn` 列透视，
  `python -m quant lake turnpanel --cutoff 2024-12-31` 约 10 秒重建。153 只在 2024-12-31 后上市、
  窗口内全 NaN，被 pivot 丢弃（下游按 panel 重索引自动为 NaN；`pyarrow.dataset(dir)` 会因 `failures.json` 报
  `Parquet magic bytes not found in footer`，必须传显式文件列表）。

- **双日期**是这层的核心设计：`event_date`（发生日）与 `available_date`（PIT 可见日）。龙虎榜/ST/分红用发生日
  （收盘后或公告日当天可见）；回购用「最新公告日期」；增减持用「变动日 **+2 个交易日**」（`refdata.trade_days()`
  + `searchsorted`）。因子矩阵只按 `available_date` 对齐，早于可见日不会出现数值（`tests/test_events.py` 钉住）。
- 三个坑：
  1. **ST 翻转必须先把 bool 列 `fillna(False).astype(bool)` 再 `shift`**：pandas 把含 NaN 的 bool 列升成 object，
     `~False` 会算成整数 −1（真值），于是「每天都是翻转日」——初版刷出 307,100 行，修完是 1,353 行。
  2. **增减持的可见日会超出交易日历**：日历末端的事件推不出 +2 日，34 行（`pit_missing`），已写进偏差声明。
  3. **龙虎榜 `post_1d..post_10d` 是接口自带的未来收益**，只做研究展示，绝不进因子（红线圈死）。
- holdout 锁：抓取覆盖到 2026-10，但 `quant.events.load()` 默认 `available_date <= 2024-12-31`；
  523,485 行里 **88,892 行（2025+ 可见 88,858 + 无可见日 34）在读入时被裁掉**，doctor 每次自检都会报这个数。
- 事件因子见 `quant/factors/events.py`（11 个）、研究见 `scripts/event_study.py` / `scripts/event_research.py`、
  报告见 `docs/事件因子研究报告.md`。
