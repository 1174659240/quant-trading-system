## 0. 先纠一处口径（必须你拍板，否则动工会返工）

你写的「分红送转做**向后复权**（调整历史价格、不改动最新价）」——**这个定义是前复权（qfq），不是后复权**。

- 前复权 qfq：以**最新价**为锚，把历史价往下调，最新价不变 → 你说的描述；
- 后复权 hfq：以**上市首日**为锚，历史价不动，最新价被往上放大。

现有实现 `quant/data/corporate_actions.py:apply_qfq()` 就是 qfq（`k = (P0 - cash) / (1 + bonus) / P0`，最新交易日因子恒为 1）。但仓库里 `lake.load_frames()` 的 docstring 写着「processed/holdout 已是**后复权**价」——**文档用词错了，代码是对的**。本次改造按 qfq 落地，并把文档口径统一成一句定义（写入 `schema.py` 注释 + README）。

**另一个你可能没注意的坑**：qfq 价随新分红事件**全历史漂移**（600519 在 2024-12-31 的 adj_factor=0.942013，只是因为之后还有除权）。所以：

- 若 processed 物理存 qfq 价，每年一次除权就要**重写 11 个年份分区**，与「增量只重写当年文件」直接冲突；
- 建议 processed **存不复权 OHLCV + `adj_factor` 列（标注 adj_asof 锚日）**，qfq 价由 `read(adjust="qfq")` 视图生成，避免冗余 4 列（约 4×1300 万×8B≈416MB 未压缩）与 `round(3)` 精度损失。

## 2. 红线风险：退市股与 ST（做 schema 前必须先探针）

你的红线是「退市股在历史上市区间内必须存在」，但**当前池子满足不了**：

1. `universe.csv` 来自新浪 `hs_a` **当期上市名单**（5576 只）→ 只有「现在还活着」的票，已退市的（600001 邯郸钢铁、000003 PT金田A 等）**根本不在池子里**，raw 里也没有历史。这是典型的幸存者偏差，且现状已存在。
2. 仓库里**没有 ST 历史**数据源，也没有 `is_st`/上市退市状态列。

**必须新增两类外部数据，且先用探针确认可得性（约 30–60 分钟）**：

- A. 退市股票清单：东财 datacenter（`RPT_*` 终止上市/退市板块）或交易所公开清单；
- B. 退市股历史日线：拿 3–5 个已退市代码（600001、000003、600087、000033、000405）分别打腾讯 `kline/kline`、新浪 `getKLineData`、东财 `push2his`，确认源是否仍提供；
- C. ST/名称变更历史：东财 datacenter 的股票曾用名/名称变更类接口。

**如果源不提供**：schema 照样保留 `is_st`/`list_status`/`delisted_date`，取值 `-1=未知`，并在 manifest + README + 验收报告里**显式声明缺口**——绝不伪造「全市场退市股齐全」。这一点请你在第 9 节明确表态。

## 3. 目录与后端（映射到你写的 data/）

实际根目录沿用 `D:\quant-data`（可配 `Lake(root)`），`data/` 即湖根：

```
D:\quant-data\
├─ raw\daily\<symbol>\<batch_id>.parquet     # 每批一个文件，只追加，不覆盖
├─ raw\daily\<symbol>\manifest.json          # 批次清单（源/时间/行数/SHA256）
├─ processed\daily\year=YYYY\data.parquet    # 全市场长表，一年一文件
├─ holdout\daily\year=YYYY\data.parquet      # 同上 + .LOCKED
├─ clean\                                    # 默认不落地；物化时 year=YYYY\data.parquet
├─ manifests\{raw.jsonl, processed.json, holdout.json, verify.json}
└─ meta\{calendar.csv, actions.csv, universe.csv, st_events.csv, delisted.csv, quality.jsonl}
```

- `Lake` 增加 `backend: "csv" | "parquet"`（构造参数 + `--backend`，默认 csv 直到迁移验收）→ **旧 CSV 代码路径完整保留**，两套并行、可回切。
- 增量语义：processed/holdout 追加新交易日照旧走「重写该年文件」（按年过滤后整体重写，约 100 万行/年，秒级）；raw 永远只新增批次文件。

## 5. ② schema 契约草案

### 5.1 processed / holdout（主表，长表，年份分区）

| 列 | Arrow 类型 | 单位 / 取值 | 可空 | 说明 |
|---|---|---|---|---|
| `symbol` | `dictionary<string, int32>` | 6 位代码，如 `600519` | 否 | dictionary 编码 |
| `exchange` | `dictionary<string, int32>` | `SH`/`SZ`/`BJ` | 否 | 由代码前缀推断（与 lake 现逻辑一致） |
| `date` | `date32` | 交易日（非交易日不得出现） | 否 | 读回转 `datetime64[ns]` |
| `open/high/low/close` | `float64` | 元，**不复权原始价** | 否 | >0；high≥max(o,c,l)，low≤min |
| `volume` | `float64` | **股**，≥0 | 否 | 停牌日 = 0 |
| `amount` | `float64` | 元，≥0 | 是 | 源缺失则 NaN（README 声明） |
| `prev_close` | `float64` | 元 | 是 | 首行 = open；停牌行 = close |
| `adj_factor` | `float64` | qfq 因子，最新交易日 = 1 | 否 | 锚日记录在 manifest `adj_asof` |
| `suspended` | `int8` | 0/1 | 否 | 停牌补齐行 = 1 |
| `tradable` | `int8` | 0/1 | 否 | `volume>0 and suspended==0` |
| `is_st` | `int8` | 1 是 / 0 否 / **-1 未知** | 否 | PIT 标记，来源见 §2-C |
| `list_status` | `dictionary<string,int32>` | `listed`/`delisted` | 否 | 按**当日**判断（PIT） |
| `delisted_date` | `date32` | 退市日 | 是 | 未退市为 null |

- 分区列 `year` **不写进文件**（路径 `year=YYYY` 承载，避免重复列）。
- 行顺序：`symbol, date`（让同一标的聚在同一 row group，单标的历史查询可剪枝）。`row_group_size=250_000`。
- 写参数：`compression="zstd", compression_level=3, index=False`。
- 估算：1300 万行 × 12 列 → zstd 后 **约 220–280MB**（CSV 748MB，约 1/3）。

### 5.2 raw（批次表，不复权、不改写）

| 列 | 类型 | 说明 |
|---|---|---|
| `symbol` | dict<string> | — |
| `date` | date32 | 源给的原样日期 |
| `open/high/low/close/volume/amount` | float64 | **不加工、不复权**；`amount` 可空 |
| `source` | dict<string> | `tencent`/`sina`/`akshare`/`csv`/`synthetic` |
| `batch_id` | dict<string> | `YYYYMMDDTHHMMSS` |
| `fetched_at` | timestamp[us, UTC] | 拉取时刻 |

批次清单 `raw/daily/<sym>/manifest.json`：
```json
{"batch_id":"20261017T093000","symbol":"600519","source":"tencent",
 "fetched_at":"2026-10-17T09:30:00+08:00","rows":2187,
 "first":"2016-01-04","last":"2026-10-16","sha256":"<sha256(parquet)>"}
```

### 5.3 clean（派生视图，默认不落地）

- 输入 processed 表，输出同 schema 的 DataFrame（列不变，行被过滤/值被缩尾）；
- `drop_st=True`：剔除 `is_st==1` 的行；`is_st==-1` 默认**保留并计数**（不能把未知当非 ST，也不能当 ST 丢样本）——两种语义写进 README；
- `drop_suspended=False`：保留停牌行（价与因子连续），`True` 时剔除 `suspended==1`；
- 退市股**一律保留**（过滤条件里显式禁止按 `list_status` 过滤）；
- 去极值：`method="mad"`（默认，`k=5`）或 `"winsorize"`（`lower/upper=0.01/0.99`），阈值在 `CleanConfig` 里配置化。

## 6. ③ 迁移脚本设计（`scripts/migrate_parquet.py`）

```
python scripts/migrate_parquet.py --root D:\quant-data --backend parquet \
  [--layers raw,processed] [--years 2016-2026] [--symbols 600519,000001] \
  [--dry-run] [--resume] [--allow-holdout] [--report results/parquet-migration.md]
```

阶段（每阶段可独立重跑，幂等）：

| 阶段 | 动作 | 失败处理 |
|---|---|---|
| **P0 预检** | pyarrow 可用、磁盘余量、`.LOCKED` 存在、CSV 全量清单（行数/大小/SHA256）落 `manifests/pre-migration.json`；`--dry-run` 只打印 | 任一失败即退出码 2，不写任何文件 |
| **P1 raw** | 逐 `raw/daily/*.csv`（`symbol` 强制 str、日期解析）→ 校验契约 → 写 `raw/daily/<sym>/<batch_id>.parquet` + 批次 manifest | 单只失败进 `skipped[]` 不中断；末尾汇总 |
| **P2 processed** | **从 raw parquet 重建**（不是转换旧 processed），复用 `apply_qfq` + `materialize_suspensions` + `tradable`，再按年 concat 写 `year=YYYY` | 同 P1；任何一只契约不符记录 witness |
| **P3 holdout** | 仅 `--allow-holdout` 时执行；否则**跳过并保持 CSV + `.LOCKED` 不动**（推荐默认） | 触碰校核集必须显式授权 |
| **P4 汇总** | 写 manifest（各层行数/SHA256/耗时/缺口）、`results/parquet-migration.md`；退出码非 0 表示有校验失败 | — |

关键实现约束：

- **原子写**：先写 `<target>.tmp` 再 `os.replace()`；中途中断不会留下半个 parquet；
- **幂等**：manifest 里已有同 `sha256(源 CSV + 参数)` 则跳过（`--resume` 默认开）；
- **不删旧**：CSV 原地保留（可后续 `archive/csv/` 归档，本脚本不做移动）；
- **不重算 holdout 的复权锚**：P2 的 qfq 锚取「全序列最后交易日」，与现有 CSV 一致才能 allclose 对齐。

## 7. ③ 验收脚本设计（`scripts/verify_parquet.py`）

```
python scripts/verify_parquet.py --root D:\quant-data --against csv \
  [--years 2016-2024] [--symbols ...] [--report results/parquet-verify.md] [--json]
```

分 A/B/C/D 四组，每项输出 `pass/fail + witness（标的+日期+值）`，任何 fail → 退出码 1。

**A. 与旧 CSV 的一致性（迁移验收核心）**

| 编号 | 检查 | 容差 |
|---|---|---|
| A1 | 逐标的行数相等（raw/processed/holdout 三层分别比） | 精确 |
| A2 | 日期集合完全相等；processed 最大日期 < 2025-01-01；holdout 最小日期 ≥ 2025-01-01；两层无交集 | 精确 |
| A3 | qfq 视图价 vs 旧 processed CSV 逐列 `np.allclose`（旧文件存的是 round(3)，故容差 5e-4） | atol=5e-4 |
| A4 | `adj_factor` allclose | atol=1e-9 |
| A5 | 事件表 38204 条：每个除权日的因子变化方向（k≤1）与幅度一致性抽检 200 只 | 相对 1e-6 |
| A6 | 停牌行数与 `meta/quality.jsonl` 的 `suspended_days` 逐标的相等 | 精确 |

**B. 数据质量（对 parquet 本身，不依赖 CSV）**

| 编号 | 检查 |
|---|---|
| B1 | 无负价/零价/负成交量；`high >= max(open,close,low)` 且 `low <= min(open,close,high)` |
| B2 | 每个交易日在日历内；非交易日无行；每只在其 `[上市日, 退市日]` 窗口内**每个日历日有且仅有一行** |
| B3 | `suspended==1 ⇔ volume==0`，且 `suspended==1 → tradable==0` |
| B4 | `date` 严格递增、无重复；无未来日期（>今日） |
| B5 | 最新交易日 `adj_factor==1`（容差 1e-12） |
| B6 | 退市股：`list_status=delisted` 的标的历史行数 > 0（红线检查）；`is_st` 未知比例报告 |

**C. 格式与契约**

| 编号 | 检查 |
|---|---|
| C1 | 列名/顺序/Arrow 类型与 `schema.py` 完全一致；读回无 `Unnamed: 0`（index=False） |
| C2 | `symbol/exchange/list_status` 在 parquet metadata 中为 dictionary 编码 |
| C3 | compression 全为 zstd；年份分区文件齐全（每年一个，无空文件） |
| C4 | 每文件行数 = manifest 记录；`sha256(parquet)` 与 manifest 一致 |

**D. 性能基线（供后续判断是否还要优化）**

- 全市场某年读取：`columns=["symbol","date","close"]` 耗时 vs 对应 CSV 集合；
- 单标的全历史（跨 11 个年文件）耗时；
- 体积对比（parquet vs csv，逐层）。

**输出**：`results/parquet-verify.md`（人读）+ 同名 `.json`（机读），含「缺口声明」段：缺数标的、`is_st=-1` 比例、退市股覆盖数、金额缺失比例。

## 9. 需要你拍板的 6 件事

1. **复权口径**：确认「最新价不变」= 前复权 qfq（按现有实现），还是你确实要 hfq（首日为锚，最新价被放大）？两者不可混用。
2. **processed 是否物理存 qfq 价**：我建议只存不复权 + `adj_factor`（省 416MB、避免舍入、新除权不重写全历史），qfq 用视图；你要物理落 qfq 列也行，但增量语义会变复杂。
3. **退市/ST 探针**：先花 30–60 分钟探源，再定 `is_st`/`list_status` 的填充规则；源不提供时接受「显式缺口 + -1 未知」，还是坚持要全量（那需要换数据源，可能涉及付费/爬虫，超出本期）？
4. **holdout 迁移**：默认不迁（保持 CSV + LOCK），等你授权再写 parquet——确认？
5. **clean 落地**：先纯视图（不写盘）——确认？去极值默认 MAD(k=5) 还是 winsorize(1%/99%)？
6. **旧 CSV 归档**：迁移验收通过后，是否允许把旧 CSV 移到 `archive/csv/`（只移动不删除）？还是原地留着？
