# 数据复现手册

> 目标：别人拿到本仓库后，**不依赖我的 `D:/quant-data`**，用免费公开源重新采一遍数据，并和我的数字对账。
> 数据总量 3.8 GB（其中可复现的核心层约 1.5 GB），全量重采预计 **28 小时**（不含重试），可中断、可分批。
> 手册日期：2026-10-22。工具：`scripts/reproduce_lake.py`（新增）+ 仓库自带的 `python -m quant lake ...` 子命令。

---

## 1. 一句话

```bash
# 0) 依赖
pip install pandas numpy pyarrow requests akshare baostock
# 1) 看阶段与耗时
python -m scripts.reproduce_lake --list
# 2) 从头跑（已完成的阶段自动跳过；中断后重跑同一条命令即可续跑）
python -m scripts.reproduce_lake
# 3) 只对账
python -m scripts.reproduce_lake --verify-only
```

数据默认落在 `D:/quant-data`（与我的目录结构一致）。换盘用 `--root E:/quant-data`。

## 3. 阶段、顺序与耗时

`python -m scripts.reproduce_lake --list` 会打印同一张表。顺序不能乱：参考数据 → 原始层 → 精简层 → 列式层 → 估值/财务/事件 → 另类 → 历史段。

| 阶段 | 内容 | 预计 | 可否并行 |
|---|---|---|---|
| `env` | 依赖与磁盘检查 | 1 分 | — |
| `meta` | 初始化 + 交易日历 | 2 分 | — |
| `universe` | 代码表 | 15 分 | — |
| `ref` | 行业 PIT / 股本 PIT / 申万 | 40 分 | 可 |
| `dividends` / `actions` | 分红与除权 | 15 分 | 可 |
| `raw` | 全市场日线 | 300 分 | 可（按代码段分进程） |
| `split` / `process` / `parquet` | 切 holdout、精简、列式 | 25 分 | — |
| `valuation` | 估值快照 | **420 分** | 可（`--shard i/n`） |
| `turnpanel` | 换手宽表 | 10 分 | — |
| `fund` / `mainfin` | 财务两张 | 150 分 | 可 |
| `index` / `delisted` / `events` | 指数成分、退市、事件 | 105 分 | 可 |
| `alt` | 预告/快报/解禁/质押 | 90 分 | 可 |
| `history` | 2007–2016 日线与财务 | 240 分 | 可 |
| `early` | 2001–2005（baostock） | 300 分 | **不可**（见坑 3） |
| `verify` | 对账 | 5 分 | — |
| **合计** | | **约 28 小时** | |

只复现某一层：

```bash
python -m scripts.reproduce_lake --stage ref,fund,alt     # 只跑参考数据+财务+另类
python -m scripts.reproduce_lake --from raw               # 从原始层开始
python -m scripts.reproduce_lake --stage process --force  # 强制重跑
```

## 4. 已知坑（都是我们踩过的）

1. **东财 `push2his` 会间歇性 `RemoteDisconnected`**：同一 IP 十分钟前还通。`raw` 阶段做了腾讯/新浪自动降级，重跑即可补齐。
2. **akshare 不带 timeout**：网络卡住会永久阻塞。采集脚本统一 `socket.setdefaulttimeout(25)`；自己写脚本时也要设。
3. **baostock 不能并发 login**：多进程同时登录会触发风控，返回 `10001011 黑名单用户`，且此后每只都"成功返回空表"（错误被吞）。`early` 阶段因此固定单进程 + 每进程一个连接；`history` 阶段用"多个独立进程、每进程串行"而不是进程池。
4. **东财批量财务的 `公告日期` 是修订后最新公告日**（如 2012 报告期给 2024-04-30）→ 不能做 PIT。历史财务必须用带 `pubDate`/`NOTICE_DATE` 的接口（本仓库用东财 `period_frame` 同源接口）。
5. **财务是修订后值**：每报告期一行、会被后续更正覆盖，所以有轻微后视偏差（已写入 15 条偏差声明）；`NOTICE_DATE` 有约 1.9 次/公司的修订痕迹。
6. **商誉缺失 ≈ 无商誉**：2024 年 5,013 家里 49% 的 `GOODWILL` 为空、显式 0 只有 125 家 → 按 `fillna(0)` 处理，并做敏感性检查。
7. **负基期**：有增速字段的 21 万条里 18.17% 的基期扣非 ≤ 0；负基期"增速"无意义 → 代码里要求两端 TTM 均 > 0。
8. **2017-09 之前研发费用覆盖率断崖**（2016-12 仅 0.3%，2017-09 跳到 76.3%）→ 研发因子只能 2018 起用。
9. **季报财务含"上市前"历史**（招股书口径）：2017-12 期有 869 只当时未上市的公司带 2013–2017 数据 → 散列时必须叠加 `ipo_date` 掩码，否则前视。
10. **`A#####` 伪代码**：财务表 8.4% 的行是这种占位代码，必须 `^\d{6}$` 过滤。

## 5. 对账

```bash
python -m scripts.reproduce_lake --verify-only
```

会拿 `docs/data-reference-counts.json`（本仓库维护者在完整湖上生成的计数）逐层比较**文件数**和**行数**：

| 层 | 文件 | 行数 |
|---|---|---|
| raw/daily | 5,575 | — |
| processed/parquet | 9 | 8,557,867 |
| holdout/parquet | 2 | 2,343,739 |
| valuation | 5,482 | 12,379,912 |
| fundamentals | 275 | 1,402,823 |
| ref | 7 | 255,673 |
| events | 6 | 523,485 |
| alt | 4 | 1,376,933 |
| delisted | 256 | 536,732 |
| growth-history/parquet | 10 | 5,264,940 |
| early/parquet | 5 | 1,491,434 |

- 全 ✓ 表示数据层与我的完全一致，可以复现 `results/` 下的所有数字。
- **允许有差异的项**：`raw/daily` 的文件数会随退市/新上市变化；`valuation` 缺个别停牌股；`growth-history` 有 298 只源侧缺口（已在 `results/crisis-generalization/early-data.md` 声明）。差异应按「层」记录在 issue 里，不要改参考计数。
- 维护者更新数据后重生成参考计数：`python -m scripts.reproduce_lake --snapshot`。

## 6. 复现完之后能跑什么

数据齐了，下列命令可直接复现各策略报告里的数字（口径见 `docs/策略报告/README.md`）：

```bash
python tests/run_all.py                                   # 210 项离线测试，不需要数据湖
python -m scripts.growth_backtest                         # 成长策略样本内（P/Q/QN/M 四规格）
python -m scripts.growth_holdout                          # 成长策略 holdout 一次性验收（会报已消费）
python -m scripts.risk_system --sample main               # 极端风险层 A/B/E/C5k
python -m scripts.growth_leftside --sample history --risk leftside
python -m scripts.final_spec                              # 红利低波基线
python -m scripts.improvement_shadow                      # 红利低波增强（只改执行）
```

> 注意：`growth_holdout` 的结果已被正式消费一次（2025-01-02~2026-10-16），再跑属于**重复观测**，不能当独立样本用。这条纪律写在 `docs/策略报告/小盘成长.md` 与 holdout 报告里。

## 7. 不在这份手册范围内

- 数据湖之外的另类源（股吧 `alt/raw/gdhs`、两融 `alt/raw/margin`）：有落盘但未进任何策略，复现脚本不覆盖。
- 逐笔/分钟线：没有。
- 付费源（Wind/聚源/朝阳永续一致预期）：不使用，也没有替代方案；因此"分析师预期修正"类因子在本项目不可做。
