# 插件与安全审计（量化交易系统配套）

> 记录时间：2026-10-17 · 宿主版本 `DSH 0.2.0-rc.2` · 配置目录 `C:\Users\abc11\.dsh\profiles\desktop\`
> 审计口径：**兼容性 + 系统安全优先；有疑点宁可不装。**

这份文档回答三件事：**装了什么、为什么没装别的、凭什么说它安全**。
所有结论都来自本机实测（包内代码逐文件扫描 + 市场兼容性预检），不采信插件自述。

## 0. 本机安装通道的现实约束（重要）

`github.com` 这一跳在本机**不通**（8s 超时），而 `codeload.github.com` / `raw.githubusercontent.com` /
`api.github.com` / `registry.npmjs.org` 都可用。后果：

- 一切 `github:owner/repo`、`dsh plugin add owner/repo` 形式的安装**必然失败**（报 `connection to github.com timed out after 5000ms`），
  这也包括插件市场 GUI 里的安装按钮；
- 可用替代通道：`dsh plugin --profile desktop add https://codeload.github.com/<owner>/<repo>/tar.gz/refs/heads/<branch>`
  （分支名用 `https://api.github.com/repos/<owner>/<repo>` 的 `default_branch` 查）；
- 后台作业里的脚本**不能存成 `.ps1` 再调用**（本机执行策略禁止脚本文件），必须把脚本体内联进 `pwsh -Command`。

### 1.1 两个必须知情的副作用

1. **`dsh-kline` 会自动准备 Python 运行环境**：首次启用时它在 `C:\Users\abc11\AppData\Local\dsh_kline\venv`
   用 `python -m venv` + `pip install` 装依赖（本机实测进行中，日志 `…\dsh_kline\bootstrap.log`），
   并 `spawn` Python 子进程提供图表服务（`server.py` / `chart_service.py`）。
   想关掉这种自动安装：启动 DSH 前设 `DSH_KLINE_RUNTIME_MODE=external`（只校验不自建），或卸载该插件。
2. **`dsh-stock-watch` 会向每个会话注入关键词工作流**：它在 host 端注册了条件式系统提示——
   消息以「每日复盘 / 行情分析 / 涨停分析」开头时执行固定的 A股复盘框架（`index.js:653-664`），
   由侧栏胶囊的扇形菜单触发。这是它的设计行为，但确实改变了全局会话行为；不想要就卸载它。

### 安全审计怎么做的

本工程自带体检工具 **`tools/audit_plugins.mjs`**（Node ≥18，无第三方依赖，可反复运行）：

```powershell
# 在项目根目录；默认审上面这 5 个插件
node tools/audit_plugins.mjs
node tools/audit_plugins.mjs my-app dsh-stock-watch   # 审指定包（含已卸载的，会报「未安装」）
node tools/audit_plugins.mjs --json                   # 机器可读
# 换 profile 时用环境变量：$env:DSH_PROFILE_DIR="C:\path\to\profile"
```

它对每个包（解析 pnpm 符号链接到真实目录，跳过 `node_modules`/`vendor`/`dist`/`.git`）逐文件统计五类信号：

1. 所有 `http(s)://` 主机 → 区分 https 与**明文 http**（含 `localhost:port` 与本地监听端口）；
2. `process.env.*` 读取的变量名 → 挑出形似密钥的（`*_KEY/_TOKEN/_SECRET/_PASSWORD/_CREDENTIAL/_COOKIE`）；
3. `child_process` / `execSync` / `spawn` / `exec(` / `eval(` / `new Function` / `createRequire` / `writeFileSync` / `listen(`；
4. 判定三态：`REJECT`（有明文 http 外联）／`REVIEW`（读疑似凭证变量 + 联网）／`PASS（静态扫描）`；
5. 主机名做形状校验、并剔除徽章/schema/XML 命名空间等非业务 URL，避免把 JS 字符串碎片误判成外联。

判定口径：**出现「明文 http 外联」或「读凭证 + 联网」的组合就不装**；只有「功能性副作用」
（起本地服务、建 venv、注入提示词）才交由用户权衡，并在 §1.1 明写。
工具只看静态信号，不等于形式化验证——所以 `REVIEW` 项（`dsh-kline`）在这里是被人工放行的，理由写在 §1.1。

## 6. 怎么撤销 / 怎么复装

```powershell
# 看当前状态（等价于插件市场里的已装列表）
dsh plugin --profile desktop ls

# 卸载本项目加的插件（会同时从 bundles / 补丁层 / 市场记账移除）
dsh plugin --profile desktop remove @v587d/capital-generation dsh-fund-research
dsh plugin --profile desktop remove "@ftshare-lab/dsh-kline" dsh-stock-watch dsh-bayes-predict

# 换 codeload 通道复装（github.com 直连在本机不通）
dsh plugin --profile desktop add https://codeload.github.com/FTShare-Lab/dsh_kline/tar.gz/refs/heads/main

# 重新打开小说插件（子命令以 dsh plugin --help 为准）
dsh plugin --profile desktop enable dsh-novel-writer
```

> `dsh-kline` 卸载后，`C:\Users\abc11\AppData\Local\dsh_kline`（含 venv）可手工删除。
> `dsh-stock-watch` 卸载后，它注入的三个关键词工作流随之消失（需重启 DSH 生效）。

## 7. 和本工程的边界

以上插件都在「对话里做研究/看行情」这一侧工作，**不向本工程的 Python 进程提供数据接口**：
`capital-generation` 是运行时联网取数（无本地离线数据湖），`dsh-kline` 的 venv 只服务它自己的图表服务。
所以 Python 引擎的取数仍走 CSV / akshare / 合成数据，见 `README.md` 的「和 DSH 里的金融插件怎么分工」。
