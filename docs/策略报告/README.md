# 策略报告总目录

这个目录放**每条策略一份的「总体情况介绍」**——不是研究底稿，也不是某次实验的结论，而是「这条策略是什么、怎么跑、能期待多少、哪里会坏、怎么复现」。

## 阅读顺序

1. 先看每份报告的 **§0 一句话** 和 **使用边界**，判断这条策略是否适合当前用途；
2. 再看业绩表（样本内 + 样本外 + 基准）；
3. 最后看复现命令——所有数字都能用仓库内脚本重算。

## 报告固定结构（新增策略照此写）

`元信息表 → 0 一句话 → 1 定位与预期 → 2 策略定义（池/因子/合成/组合/执行/风控/成本） → 3 数据与 PIT → 4 业绩（样本内/历史/holdout/拼接） → 5 稳健性 → 6 已知缺陷与使用边界 → 7 复现与产物 → 8 变更历史`

## 「保存一条策略」的含义（本仓库约定）

一条策略被「保存/冻结」需要同时具备四件东西：

1. **报告**（本目录下的 md，口径、业绩、边界、复现齐备）；
2. **台账**（`registry.json` 里的一条记录，机器可读的冻结参数与产物路径）；
3. **git 提交 + 标签**（例如 `v1.0-growth-cap25-20261022`，指向可复现的代码状态）；
4. **冻结后的纪律**：改因子/参数/规则即视为新版本，旧报告的样本外结论作废，需重新封存再验。
